# Перенос PyStudio на статический веб-хостинг

PyStudio не требует PHP, Node.js, базы данных или другого серверного кода.
Готовую сборку можно распаковать и загрузить на любой статический веб-хостинг.

## Получение готовой сборки

1. Откройте вкладку **Actions** репозитория на GitHub.
2. Выберите успешно завершившийся запуск **Deploy autonomous editor to GitHub Pages**.
3. В разделе **Artifacts** скачайте `pystudio-static-site`.
4. Распакуйте скачанный архив `pystudio-static-site.zip`.

Внутри готовой сборки должны находиться:

```text
index.html
logo.webp
vendor/
  pyodide/
```

## Загрузка на хостинг

Загрузите **содержимое** скачанного архива в публичный каталог сайта,
например `public_html`, `www` или `htdocs`. Файл `index.html` и каталог `vendor`
должны находиться на одном уровне. Сборку можно размещать как в корне домена,
так и в подкаталоге: пути к Pyodide вычисляются относительно `index.html`.

Хостинг должен:

- отдавать статические файлы без их переименования;
- разрешать загрузку файлов `.wasm`, `.zip`, `.whl` и `.js`;
- желательно отправлять `.wasm` с типом `application/wasm` (это позволяет
  браузеру компилировать модуль потоково). Редактор также поддерживает хостинги,
  которые отдают корректный `.wasm` как `application/octet-stream`: в этом
  случае модуль автоматически загружается целиком перед компиляцией;
- работать по HTTPS, как большинство современных статических хостингов.

В частности, проверьте прямое открытие файла Pillow из `vendor/pyodide/`
(точное имя указано в `vendor/pyodide/pyodide-lock.json`). Некоторые хостинги
по умолчанию запрещают расширение `.whl`; его необходимо разрешить в настройках
статических файлов. Если локальный `.whl` всё же недоступен, редактор попробует
загрузить пакет с CDN сборки Pyodide 0.27.7. Для этого хостинг и браузер не
должны блокировать HTTPS-запросы к `cdn.jsdelivr.net`.

После загрузки откройте сайт, запустите простой пример Python, затем проверьте
его с отключёнными внешними запросами в инструментах разработчика браузера.
Все файлы рантайма должны загружаться с того же домена, на котором размещён
редактор.

## Если Python долго загружается

При первом запуске редактор создаёт Web Worker и загружает из
`vendor/pyodide/` сам Pyodide, WebAssembly-модуль и стандартную библиотеку
Python. Поэтому быстрая загрузка `index.html` ещё не означает, что хостинг так
же быстро отдаёт крупные файлы рантайма. Режим инкогнито использует отдельный
пустой кеш и не исключает проблему на стороне хостинга.

Если после нескольких минут ожидания сайт без каких-либо изменений снова
начинает работать, наиболее вероятны временная перегрузка хостинга, ограничение
скорости или числа запросов, перезапуск узла либо обновление кеша/CDN. Для
проверки:

1. Откройте **Network** в инструментах разработчика, включите сохранение журнала
   и запустите программу. Проверьте время, статус и размер запросов к
   `pyodide.js`, `pyodide.asm.wasm`, `python_stdlib.zip` и
   `pyodide-lock.json`. Статусы `429`, `502`, `503` и `504`, долгое ожидание
   первого байта или запрос со статусом `(pending)` указывают на сервер, прокси
   или CDN, а не на выполнение Python.
2. С другой сети или сервера измерьте каждый файл отдельно (заменив домен):

   ```bash
   curl -L --fail --output /dev/null \
     --write-out '%{http_code} %{size_download} bytes %{time_starttransfer}s TTFB %{time_total}s total\n' \
     https://example.com/vendor/pyodide/pyodide.asm.wasm
   curl -L --fail --output /dev/null \
     --write-out '%{http_code} %{size_download} bytes %{time_starttransfer}s TTFB %{time_total}s total\n' \
     https://example.com/vendor/pyodide/python_stdlib.zip
   ```

   Повторите команды во время проблемы и после её исчезновения. Это отделяет
   скорость ответа хостинга от скорости браузера или провайдера пользователя.
3. Сравните размеры файлов на сервере с файлами из artifact. Ответы должны быть
   полными, без HTML-страницы ошибки вместо `.wasm` или `.zip`. Проверьте в
   журналах хостинга запросы с кодами `4xx`/`5xx`, лимиты трафика, CPU/I/O,
   число одновременных соединений и события перезапуска за тот же интервал.
4. Настройте для версионированных файлов в `vendor/pyodide/` длительное
   кеширование в браузере и CDN, например
   `Cache-Control: public, max-age=31536000, immutable`. Для `index.html`
   используйте короткий кеш или перепроверку (`no-cache`), чтобы новая версия
   страницы не ссылалась на неполностью загруженный каталог `vendor`.
5. Публикуйте новую сборку атомарно: сначала загрузите весь каталог во временное
   место, проверьте наличие файлов, затем переключите публичный каталог. Это
   исключает кратковременные `404` во время обновления.

Редактор заранее запрашивает самые крупные файлы Pyodide уже при открытии
страницы, чтобы к нажатию кнопки «Запустить» они оказались в HTTP-кеше. Для
этого сервер должен разрешать обычные same-origin-запросы и корректно
кешировать ответы. Попытка запуска всё равно прекращается через 60 секунд:
предварительная загрузка уменьшает время ожидания, а не маскирует медленный или
зависший сервер увеличенным тайм-аутом. Если в Network все перечисленные ответы
имеют
статус `200`, полностью скачиваются быстро, но инициализация всё равно не
завершается, проверьте ошибки Worker/WebAssembly в Console, расширения и
антивирусную веб-фильтрацию, а также попробуйте другой браузер. Если задержка
воспроизводится одновременно у разных пользователей и исчезает сама, следует
обратиться к хостеру с точным временем, URL медленного файла и данными TTFB.

> Архив исходного кода репозитория сам по себе не является готовой сборкой:
> крупные файлы Pyodide добавляются workflow при сборке. Для ручного переноса
> используйте именно artifact `pystudio-static-site`.
