# Перенос PyStudio на статический веб-хостинг

PyStudio не требует PHP, Node.js, базы данных или другого серверного кода.
Готовую сборку можно распаковать и загрузить на любой статический веб-хостинг.

## Получение готовой сборки

1. Откройте вкладку **Actions** репозитория на GitHub.
2. Выберите успешно завершившийся запуск **Deploy autonomous editor to GitHub Pages**.
3. В разделе **Artifacts** скачайте `pystudio-static-site`.
4. Распакуйте скачанный архив `pystudio-static-site.zip`.

Внутри готовой сборки должны находиться:

```text
index.html
logo.webp
vendor/
  pyodide/
```

## Загрузка на хостинг

Загрузите **содержимое** скачанного архива в публичный каталог сайта,
например `public_html`, `www` или `htdocs`. Файл `index.html` и каталог `vendor`
должны находиться на одном уровне. Сборку можно размещать как в корне домена,
так и в подкаталоге: пути к Pyodide вычисляются относительно `index.html`.

Хостинг должен:

- отдавать статические файлы без их переименования;
- разрешать загрузку файлов `.wasm`, `.zip`, `.whl` и `.js`;
- желательно отправлять `.wasm` с типом `application/wasm`;
- работать по HTTPS, как большинство современных статических хостингов.

После загрузки откройте сайт, запустите простой пример Python, затем проверьте
его с отключёнными внешними запросами в инструментах разработчика браузера.
Все файлы рантайма должны загружаться с того же домена, на котором размещён
редактор.

> Архив исходного кода репозитория сам по себе не является готовой сборкой:
> крупные файлы Pyodide добавляются workflow при сборке. Для ручного переноса
> используйте именно artifact `pystudio-static-site`.
